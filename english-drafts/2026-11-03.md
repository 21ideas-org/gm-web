## Security & Privacy

#### BTCPay Server warns of reported hot-wallet thefts on version 2.4.1 and earlier

Reports of stolen bitcoin and litecoin surfaced on 1 November, prompting an emergency shutdown warning. Nicolas Dorier says the attacker logged in as admin on affected instances by a still-unknown method; public servers on 2.4.7 were not attacked. [blog.btcpayserver.org](https://blog.btcpayserver.org/btcpay-server-security-incident-2-4-1-and-earlier/) [x.com](https://x.com/BtcpayServer/status/2117106240098611681)

## Lightning & L2

#### Liquid Federation says bitcoin reserves are fully restored, with all LBTC backed 1:1 again

The milestone follows the restoration of BTC<>LBTC swaps several weeks ago; the Federation says node operators can verify its Proof of Reserves. JAN3 says it fulfilled Lightning swaps at 1:1 from its own reserves throughout. [x.com](https://x.com/Liquid_BTC/status/2117407283391214047) [x.com](https://x.com/AquaBitcoin/status/2117409139622392079)

#### Core Lightning nodes can keep crashing after an upgrade until a stored trigger is removed

The flaw was patched in April, but a malicious announcement already saved on an affected node must be removed separately. [cryptoslate.com](https://cryptoslate.com/core-lightning-nodes-can-keep-crashing-after-an-upgrade-because-the-trigger-stays-on-disk/)

#### Preprint estimates 71% of flagged LND nodes still lack year-old Lightning security fixes

The October 21 preprint estimates that 71% of an exposed LND cohort remained on affected release lines as of its October 13 cutoff. [cryptoslate.com](https://cryptoslate.com/bitcoin-lightnings-year-old-security-fixes-still-missing-from-71-of-flagged-nodes/)

#### Eclair release tightens funding rules after unconfirmed inputs put Lightning payments at risk

The October 27 release requires confirmed peer inputs for splices by default and improves recovery when a channel must close with funding still pending. [cryptoslate.com](https://cryptoslate.com/eclair-tightens-bitcoin-funding-rules-after-unconfirmed-inputs-put-lightning-payments-at-risk/)

## Technology & Development

#### Lean 4 proof by dni backs 128-bit randomizers for BIP340 batch verification

Proposals to shrink the randomizers from 256 to 128 bits would speed up libsecp256k1 batch verification by up to about 9%. The proof covers both deterministic derivations; the cost is offline grinding, about 2^64 hashes for a ~2^-64 chance of an invalid batch passing. [delvingbitcoin.org](https://delvingbitcoin.org/t/machine-checked-soundness-of-bip340-batch-verification-with-128-bit-derived-randomizers/3019) [github.com](https://github.com/sipa/bips/issues/219)

#### satd node software adds optional full OP\_RETURN value pruning

Its author, bkeroack, calls satd the first node implementation to offer it: operators can prune OP\_RETURN values above a chosen size in blocks at least 288 deep. The author presents it as a response to the BIP-110 controversy that does not break consensus. [delvingbitcoin.org](https://delvingbitcoin.org/t/full-op-return-value-pruning/3026) [delvingbitcoin.org](https://delvingbitcoin.org/t/cost-bounded-transaction-filtering-language/2966)
