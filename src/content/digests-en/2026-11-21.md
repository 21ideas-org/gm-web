## Security & Privacy

#### Bitcoin Core discloses medium-severity node-stall bug, fixed in 30.5, 31.3 and 32.1

A peer could temporarily halt block and transaction processing by repeatedly announcing an orphan. Affected: 29.0–29.5, 30.0–30.4, 31.0–31.2; end-of-life 29.x gets no fix. Found by an automated LLM scan in Spiral's Project Loupe. [bitcoincore.org](https://bitcoincore.org/en/2026/11/20/disclose-orphan-inv-stall/) [github.com](https://github.com/project-loupe/loupe)

#### Reflected XSS found in LNbits /lnurlwallet endpoint

A crafted link or QR code could run JavaScript in the LNbits instance's origin and ride a victim's logged-in session to read balances and payment history or mint API keys, without the password. [github.com](https://github.com/lnbits/lnbits/security/advisories/GHSA-g7c6-hwmg-j9v8)

## Technology & Development

#### Bitcoin Optech Newsletter #432: decentralized pool payouts and an Eclair DoS disclosure

The issue covers an analysis of decentralized mining pool payouts, the disclosure of a fixed denial-of-service vulnerability in Eclair, and continued debate on whether stale tip relay should include block data. [bitcoinops.org](https://bitcoinops.org/en/newsletters/2026/11/20/)

#### adiabat outlines ideas for a post-quantum recovery framework

The post sketches consensus changes that would add spending conditions to existing UTXOs to protect them if elliptic-curve security breaks, focusing on unprepared schemes that assume users took no action before Q-day. [delvingbitcoin.org](https://delvingbitcoin.org/t/post-quantum-recovery-framework/3099) [delvingbitcoin.org](https://delvingbitcoin.org/#p-9093-what-is-pq-recovery-prepared-and-unprepared-1)

#### bkeroack proposes a Node Attestation Protocol to survey economic nodes

The proposed protocol would let participants publish key-value attestations backed by proof of UTXO control over a new P2P message; an aggregator would weight results by coin value, offering a broader survey than miner signaling. [delvingbitcoin.org](https://delvingbitcoin.org/t/node-attestation-protocol/3100) [bitcoin.com](http://bitcoin.com/)

#### ariard raises a hypothetical "slow-sliding MTP" attack under BIP 54

Reviewing BIP 54's timestamp rule for the first block of a difficulty period, ariard asks whether whoever sets the prior block's time could sway the next block's validity, while judging it not enough to outweigh BIP 54's security benefit. [delvingbitcoin.org](https://delvingbitcoin.org/t/open-question-on-a-hypothetical-minor-slow-sliding-mtp-attack-introduced-by-bip-54/3101) [groups.google.com](https://groups.google.com/g/bitcoindev/c/tKETFYnEtng)
